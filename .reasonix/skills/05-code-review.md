# 🔍 代码审查

基于 addyosmani/agent-skills (48.8k⭐) 的生产级工程实践。

## 何时使用
- 「review 一下」「帮我看下这段代码」「检查有没有问题」
- 提交或合并重大变更前

## 审查清单

### 1. 正确性
- 代码是否做到了该做的事？边界情况处理？错误路径覆盖？

### 2. 安全性
- 输入校验？SQL注入/XSS/路径遍历？硬编码密钥？权限检查？

### 3. 性能
- N+1查询？不必要的循环？缓存？内存泄漏？

### 4. 可维护性
- 命名清晰？DRY？函数小而专注？复杂部分有注释？

### 5. 架构
- 遵循项目模式？关注点分离？可测试？

## 输出格式
```markdown
## 代码审查：[文件/PR]

### 总结 [1-2句]

#### 🔴 严重（必须修复）
- **文件:行号** — 问题 → 修复建议

#### 🟡 警告（应该修复）
- **文件:行号** — 问题 → 修复建议

#### 🟢 建议（锦上添花）
- **文件:行号** — 想法 → 好处

### 总评：[1-10分] — [一句话]
```
